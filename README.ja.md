# Copilot 用 OpenRouter：カスタムリクエストとクレジット確認

Copilot Chat に**カスタマイズ可能な OpenRouter プロバイダー**を登録する VS Code 拡張機能です。Copilot 組み込みの OpenRouter プロバイダーでは、OpenRouter の `provider` ルーティングオブジェクトや `session_id` を送信できません（microsoft/vscode#283201、microsoft/vscode-copilot-release#11420）。この拡張機能は Copilot の CAPI プロキシを経由せずに OpenRouter を直接呼び出すため、貼り付けた任意のリクエストボディオプションをすべての Chat リクエストに適用できます。また、使用中のキーのクレジット使用量も追跡します。

## できること

- **モデルピッカー:** Copilot Chat のモデルピッカーに、OpenRouter カタログを含む「OpenRouter: RC」グループを追加します。既定では、このキーで利用できないモデルを非表示にします（これ以外に、クライアント側でモデルを制限することはありません）。
- **貼り付けたリクエストの適用:** [OpenRouter Request Builder](https://openrouter.ai/request-builder) のリクエストボディを貼り付けます。そこに含まれる `provider` ルーティング、サンプリングパラメーター、`response_format`、`plugins`、`transforms`、`cache_control` などの設定が、クリアまたは置き換えるまで、すべてのリクエストにそのまま適用されます。
- **プリセット:** OpenRouter アカウントのプリセットを選択すると、そのルーティングがすべてのリクエストに適用されます。モデルを固定するプリセットは `@preset/<slug>` のピッカー項目としても表示されます（ピッカー項目が作られるのはモデル固定のプリセットのみです。ピッカーのクエリごとに最大 25 件のプリセット設定を取得します）。
- **このキーで利用できないモデルを非表示**（既定でオン）：アカウントが利用できるモデルの一覧に基づき、利用できないモデルをモデルピッカーから除外します。オフにするとカタログ全体を表示します。
- **推論の強度:** 推論モデルでは、VS Code 標準の推論強度セレクター（またはシンプルなオン/オフ切り替え）を利用でき、推論トレースもチャットに表示されます。
- **Anthropic キャッシュ:** Anthropic 系モデル（`anthropic/*`、`~anthropic/*` を含む）には、貼り付けたリクエストボディで別途設定されていない限り、トップレベルの `cache_control` が自動的に追加されます。
- **モデルカード:** ピッカー項目には、100 万トークンあたりの推定加重平均価格、コンテキストウィンドウ、最大出力、各種機能が表示されます。OpenRouter が長コンテキストのしきい値を超えるリクエストに割増料金を適用する場合（例：OpenAI GPT で 272K トークン超）、基本価格と段階別価格も表示します。
- **コンテキストサイズ:** 長コンテキスト向けの価格段階があるモデルでは、ピッカーの **Context size** メニューにモデルの固定サイズ（価格段階ごとに 1 つと、ウィンドウ全体）が**プロンプト予算**として表示されます。Copilot はこの予算に出力予約を加えます。小さな予算には停止マーク（`<64K`）または警告（`≤128K`）が表示されます。未選択のモデルでは、256K に最も近い価格段階（196K 以上）が既定になります。モデルごとのコンテキストサイズを設定できるのはここだけです。パネルにコンテキストタブはありません（グローバルの出力予約設定は引き続き適用されます）。
- **使用済みコンテキストサイズ:** 各ターンは OpenRouter 自身の `usage` チャンク（プロンプト/補完トークン、キャッシュ読み取り）を Copilot に転送するため、コンテキスト使用量リングに*使用済み / 最大トークン*が表示されます。
- **セッション支出:** パネルの「セッション支出」セクションでは、このウィンドウ内で各チャットセッションにかかった費用を集計し、プロバイダーとモデル別に折りたたみ可能な内訳を表示します（詳細は下記）。チャット履歴には何も追加されません。
- **チャットごとに 1 つの OpenRouter セッション:** `session_id` にはチャット固有の永続 ID を使うため、ウィンドウを再読み込みしても各ターンは 1 つの OpenRouter セッションにまとまります（スティッキールーティングと Logs → Sessions ビューに反映）。完全再起動後も保持される設計ですが、検証はしていません。新しいチャットには新しい OpenRouter セッションが割り当てられます。バックグラウンド/内部呼び出し（サブエージェントや Copilot 自身のユーティリティフロー）は、呼び出し元のチャットに紐づきます。該当するチャットがない場合は `session_id` を送信せず、不要なセッションを作成しません。
- **ステータスバー:** 残りのクレジットを表示します。パネルには使用状況ダッシュボードがあります。

ホスト管理のフィールドは常に置き換えられます。`model`、`messages`、`tools` は Copilot が指定し、`stream` は常に `true` です。`session_id` には拡張機能がチャットごとに割り当てる ID を使い、プロンプトキャッシュを維持します。貼り付けた `prompt` は破棄されます。それ以外の貼り付けたフィールドはすべて適用されます。推論の強度と有効/無効はピッカーで設定し、`reasoning.effort` / `reasoning.enabled` のみを上書きします。

## パネル

1 つの Webview **「Copilot 用 OpenRouter」** に、**キー情報**、**セッション支出**、**設定** の 3 つのタブがあります。ステータスバー項目（**OR …**）または「OpenRouter: プロバイダーを管理」コマンドから開きます。長コンテキスト料金が適用されるモデルのコンテキストサイズは、パネルではなくモデルピッカーの **Context size** メニューで設定します。

## インストール（VSIX から）

この拡張機能は VSIX としてのみ配布されます。VS Code の提案 API（`chatProvider`、`languageModelThinkingPart`）を使用しており、Marketplace には公開されていません。

1. ビルド：`npm install && npm run package` → `openrouter-copilot-request-credit-<version>.vsix`。
2. VS Code → 拡張機能 → 「…」 → **VSIX からインストール…** → ファイルを選択。
3. パネルを開き、OpenRouter キー（OS のキーチェーンに保存されます）を貼り付けます。
4. Chat で **OpenRouter: RC** グループからモデルを選び、他の Copilot モデルと同様に使用します。

## 使い方

1. [openrouter.ai/request-builder](https://openrouter.ai/request-builder) でリクエストを作成し、JSON ボディをコピーします。
2. **カスタムリクエスト** ボックスに貼り付け、**リクエストを保存** を選択します（検証され、エラーは報告されます）。
3. 以降のすべての Copilot Chat リクエストは、クリアまたは置き換えるまでそれに従います。

## 設定

| 設定 | 既定値 | 説明 |
| --- | --- | --- |
| `openrouterCopilot.creditLimit` | `0` | USD でのローカル支出上限（`0` で無効になり、アカウント全体の残高を表示します）。 |
| `openrouterCopilot.creditResetPeriod` | `daily` | ローカル支出上限のリセット周期：`daily` / `weekly` / `monthly` / `never`。 |
| `openrouterCopilot.creditIncludeByok` | `true` | BYOK の使用量を支出上限の計算に含めます。 |
| `openrouterCopilot.creditRefreshIntervalMinutes` | `5` | 使用量の更新間隔（1〜1440 分）。 |
| `openrouterCopilot.sanitizeBase64Content` | `true` | 組織のガードレールによってリクエストがブロックされないよう、リクエストテキスト（メッセージ、推論、ツール呼び出し引数。画像添付は対象外）から長い base64 風の文字列を削除します。 |
| `openrouterCopilot.hideUnavailableModels` | `true` | このキーでは使用できないモデルをモデルピッカーから非表示にします。可用性クエリに失敗した場合は完全なカタログにフォールバックします。 |
| `openrouterCopilot.outputReservePercent` | `12.5` | コンテキストウィンドウに対する出力予約の目標割合（%）。OpenRouter が実際の最大補完上限を公表していない場合に使用します（1〜50）。 |
| `openrouterCopilot.outputReserveMinTokens` | `16384` | 出力予約の下限（トークン）。極小のウィンドウでも妥当な返信予算を確保します。 |
| `openrouterCopilot.outputReserveMaxTokens` | `262144` | 出力予約の上限（トークン）。実際に公表された上限はここで制限されます。両方の制限を同じ値にすると固定の予約になります。 |

9 つの設定はすべてアプリケーションスコープです。ワークスペース設定からプロバイダーや使用量に関する設定を変更することはできません。プロバイダー関連およびクレジット関連のリクエストは、固定の OpenRouter API エンドポイントに送信されます。

**出力予約:** コンテキストウィンドウから返信用に確保する予算です。OpenRouter が実際の最大補完上限を公表していない（または仮の上限値だけを公表している）場合、拡張機能は `outputReservePercent` に基づく量を予約し、トークン数を下限と上限の範囲内に収めます。実際に公表された上限はそのまま使い、上限値を超える場合にのみ制限します。残りのウィンドウサイズは、モデルの入力予算として Copilot に通知されます。

## パネルでのセッション支出

パネルの **セッション支出** セクションには、各 Copilot チャットセッションの費用が表示されます（ウィンドウを再読み込みしても保持されます）。各セッションは折りたたみ可能な 1 行です。展開すると、プロバイダー/モデルのルートごとに `コスト | プロバイダー | モデル | 呼び出し | キャッシュ率` の行が表示されます。

- **チャットセッションごとに 1 エントリ**（対応する OpenRouter `session_id`）：新しい順に表示し、最新の項目は展開済みです。クリックで折りたたみ/展開できます。`<details>` を使っているため、スクリプトは不要です。
- **Copilot のチャット名を使用:** VS Code にチャットタイトルがある場合はそのタイトルを行のラベルに使います（VS Code 自身のチャットセッションストアからローカルで読み取るため、OpenRouter には送信されません）。タイトルがない場合は短い ID を使います。各行にはセッションの最終更新時刻も表示されます。
- **最大 10 エントリ:** 最近のチャットを保持します。1 つは未割り当てエントリ用に確保されるため、チャット用の枠は 9 つです。新しいチャットが追加されると、古いチャットから順に一覧から外れます。
- **内部呼び出しは直近のチャットに計上（あくまで推定で、正確な帰属ではありません）:** 会話 ID のないバックグラウンド呼び出し（サブエージェントや要約処理など）は、最後にアクティブになったチャットから 10 分以内であれば、そのチャットに計上されます。10 分を過ぎた場合、または Copilot のチャットハーネスを経由しない呼び出しの場合、支出は未割り当てに計上されます。
- **プロバイダー/モデルのルートごとに 1 行:** 1 つのセッションで複数のルートを使用できます（たとえば、ほとんどのターンは BYOK ルートで、1 ターンだけ OpenRouter ホストのモデルを使用する場合など）。ルートはコストの高い順に並びます。
- **BYOK マーカー:** 自身の上流キーが課金される場合、ルートラベルに `(BYOK)` が付きます。OpenRouter 課金のルートにはマーカーが付きません。
- **`未割り当て（チャット id なし）`:** Copilot のチャットハーネスを経由せずにプロバイダーへ到達した呼び出し（たとえば agent-host/SDK のクライアント BYOK セッション）の支出は、計上先のチャットがないため、最後の 1 エントリにまとめられます。
- **ウィンドウ全体の合計はなし:** 各セッションは自身の数値を表示します。

**どの費用が計上されるか:** OpenRouter が課金する場合（共有プールのルート）は、OpenRouter の `usage.cost` を使います。**BYOK ルートでは上流プロバイダーが課金するため、OpenRouter は `cost: 0` を報告します**。その場合、拡張機能は OpenRouter がそのターンについて報告する上流コスト（`usage.cost_details.upstream_inference_cost`）を使います。

- **ターンをまたぐ合計:** 合計は、ツールを使用するターンの個別のモデル呼び出し（Copilot はツールのラウンドごとに 1 回呼び出します）をまたいで保持されます。
- **永続化と精度:** 合計は VS Code のグローバル状態に保存されるため、ウィンドウを再読み込みしても保持されます（完全再起動後も保持される設計ですが、検証はしていません）。実際にはマイクロドル単位の金額になるため、計算に必要な精度で表示し、`$0.00` に丸められることはありません。
- **チャット履歴には含まれない:** コストをチャット履歴に書き込まないのは意図的な仕様です。Copilot 自身の応答フッター（`Model • N credits`）は拡張機能が提供するモデルでは利用できず（Copilot の CAPI 使用量を読み取るため）、応答テキストに費用を追記すると会話に混ざり、コンテキストとして再送信されてしまいます。

## 既知の制限

- **WSL および Dev Containers 上の Agents ウィンドウ / Copilot SDK:** このプロバイダーは agent-host のモデル一覧に表示されません（microsoft/vscode#332085。すべての BYOK/カスタムエンドポイントプロバイダーに影響します）。同じウィンドウ内の通常の Copilot Chat は利用でき、ローカルの Windows ウィンドウでも利用できます。
- **OpenRouter 経由の Gemini:** プロンプトキャッシュが機能しません（OpenAI→Gemini 変換層でのヒット率は 0%）。また、Gemini 3.1 のエージェントモードでは `thought_signature` が取り除かれると 400 エラーになることがあります。エージェントモードでは Gemini の使用を避けてください。
- **Qwen:** プロンプトキャッシュにはブロック単位のキャッシュマーカーが必要ですが、この拡張機能は送信しません。そのため、Qwen ルートではキャッシュ割引を見込まず、入力全体に通常の入力料金がかかるものとして見積もってください。
- **ストリームのキャンセル:** キャンセルしても課金が停止するのは、OpenRouter が対応を明記しているプロバイダーに限られます（DeepSeek と DeepInfra は対応、Google/Bedrock/Groq などは非対応）。

## 注記

- **互換性:** チャットとエージェントモード（ツール呼び出し）に対応しています。インライン補完には対応していません（BYOK と同様です）。
- **ネットワーク:** キーがマシンの外に送信されるのは、Authorization ヘッダーで OpenRouter に送る場合のみです。
- **ローカル上限:** ローカルの `limit` は表示を補助するものです。実際の上限は OpenRouter のサーバー側ガードレールが適用します。

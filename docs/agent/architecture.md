# Architecture

Module map for everything outside the language-model provider.

Provider internals (catalog, request pipeline, usage, session spend) are in [provider.md](provider.md).

- `src/extension.ts` — activation: registers the provider (`vscode.lm.registerLanguageModelChatProvider('openrouter-copilot-request-credit', …)`, vendor id must match `contributes.languageModelChatProviders[].vendor`), the status bar item (credit), the refresh lifecycle (single-flight `refresh`/abort-supersede `doRefresh`), the unified webview panel, the config-change listener and the auto-refresh timer. Commands: `openrouterCopilot.manage` and `openrouterCopilot.pasteTemplate` both open the panel; `openrouterCopilot.clearTemplate` clears the template. The status bar item is wired to `openrouterCopilot.show`, registered at runtime but intentionally not contributed to the Command Palette. Exports for tests: `refresh`, `doRefresh`, `getStatusText`, `createPanelDeps`, `stopRefreshTimerForTesting`, and `readConfig`.
- `src/panel.ts` — the **single control panel** (webview): `renderPanelHtml`, `handlePanelMessage`, `PanelDeps`, `readConfig`. Three tabs: **Key Info** (key save, credit usage and credit settings; also the **Hide models this key cannot use** toggle (`hideUnavailableModels`)), **Session Spend** (per-chat spend), and **Configurations** (top: the global **Output reserve** for P16 — target percent plus lower/upper limits entered in K (1 K = 1000 tokens, decimal like every other size), in three dot-separated field groups; below: preset dropdown and custom request JSON; selecting a preset replaces the saved request, selecting the default clears it). Per-model context-size configuration lives **only** in the model picker's **Context size** menu; the panel has no Context tab (the Output reserve controls are the global policy behind that budget). Every contributed user setting has an editable control in this panel, even when no API key/account details are available; all configuration updates use application/global scope. The active tab is retained in VS Code webview state across rerenders. Short explanatory notes are placed with the controls they describe. The preset list is fetched when the panel renders, and the dropdown re-syncs whenever the template is saved or cleared. `readConfig` reads global scope only and validates/clamps numeric, boolean and reset-period settings. Message handling and rendering are unit-testable (no live webview needed). Toggling `hideUnavailableModels` calls `resetCatalogCache()` (via the config-change listener) so the picker re-queries with the new filter. Two different refresh paths feed it, which matters when reading the panel: **credit** info is driven by the `openrouterCopilot.creditRefreshIntervalMinutes` timer, while **session spend** is event-driven (`onTurnCost` re-renders an open panel, which re-reads the store) — so after a reload the spend section shows the persisted total, and the chat's next turn *grows* that same entry instead of adding a second one.

- `src/modelInfo.ts` — pure model-card rendering for the picker tooltip (`buildModelInfo`): OpenRouter per-token pricing → per-1M display; a **plain GFM pricing table** (no heading), whose first column is `%` (the agentic-usage mix `3 uncached : 6 cache write : 85 cache read : 5 thinking : 1 output`, cache-write → input fallback), then `Type` (one row per component: uncached/cache write/cache read/thinking/output), then one column per pricing segment (`$Mtok` when flat, `≤ <bound>` / `> <bound>` when tiered), closed by a bold weighted `**Blended**` row (ratio `100`, per-column blended `~$X.XXX`); plain info lines
`Context window:` / `Effective prompt cap:` / `Effective completion cap:` / `Max completion:`, followed by one capability line each (`Tools: \u2713`, `Image: input \u2713 / output \u2717`, likewise video and audio — `architecture.output_modalities` included); and a reasoning line (`None/Low/**Medium**/High` with the default bolded, `(required)` appended when mandatory) — plus `buildReasoningSchema` (navigation-grouped Thinking Effort schema; it honors `default_enabled: false` by pre-selecting the off choice wherever one exists, and never offers `none` when `mandatory`), `effortFromModelConfiguration`, and the stepped-model **Context size** picker schema (`contextCapOptions`/`contextCapSelection`/`contextCapFromPicker`/`buildContextCapSchema`/`defaultContextCap`/`formatSize`/`sizeAdvisory`: one entry per step plus the whole window as **prompt budgets**, `sizeAdvisory` giving `<64K` a stop sign and `≤128K` a warning, `defaultContextCap` picking the step closest to 256K at or above a 196K floor; offered only for a model with a price step). Intentionally imports no `vscode`; unit-tested in `modelInfo.test.ts`.
- `src/storage.ts` — the **single shared key secret** (`openrouterApiKey`) with a 10 s bounded keychain read and one-time migration from the legacy `openrouterCopilot.apiKey` secret. Both the provider and the usage refresh read this one key.
- `src/logic.ts` — pure credit/usage derivation (`KeyInfo`, `coreView`, `buildDetail`, `buildStatus`, `maskKey`, reset math). Intentionally imports no `vscode`; unit-tested. Do not add `vscode`/network imports here.
- `src/test/` — mocha (tdd) suite: `runTest.ts` (fresh temp `--user-data-dir`, `ELECTRON_RUN_AS_NODE` guard, 10-minute timeout), `suite/index.ts`, and per-module suites (`logic`, `config`, `modelInfo`, `panel`, `extension`, `provider`). The extension and provider suites stub `globalThis.fetch` so they never hit the network or the real OS keychain (Windows SecretStorage is OS-global, not isolated by `--user-data-dir`); `provider.test.ts` also injects a no-op retry delay (`setRetryDelayForTesting`) and exercises the stream loop end-to-end with canned SSE bodies (reasoning parts, streamed errors, retries, usage chunk — including a `choices: []` usage-only chunk — and the forwarded `usage` data part), plus unit cases for `buildUsagePart` and `sessionIdFor`.

## Settings

Settings (package.json `contributes.configuration`): one **"OpenRouter for Copilot"**
section — four `openrouterCopilot.credit*` settings for the guardrail/usage dashboard,
one request-safety setting (`sanitizeBase64Content`), `hideUnavailableModels` (default **true**),
which intersects the catalog with the account's available models so the picker hides models the key cannot use,
and three output-reserve settings for P16 (`outputReservePercent` default **12.5**, range 1-50;
`outputReserveMinTokens` default **16384**; `outputReserveMaxTokens` default **262144**). All settings
are application-scoped and have a control in the panel (the reserve controls live in the Configurations tab).
API endpoints are fixed to OpenRouter.
The request template itself is pasted JSON stored via the provider's global state — it is
**not** exposed as a multi-field settings UI.
